# Review a report or compare tests

1. Read the selected run and requested baseline by ID. Respect the user's selected comparison; do not silently substitute the latest run. Read the question set and captured settings where relevant.
2. Establish completion and scored/skipped/error counts before interpreting quality. Missing scores and operational failures are not zero-quality answers. Report their separate impact on confidence.
3. Pair results by stable case ID. Compare only cases with the same question, expected answer, and required actions and finite scores in both runs. New, removed, edited, and skipped cases are not valid score-change evidence. Mention matched sample size and changes to model, prompt channel, knowledge, scoring, or enabled actions that limit causal claims. Percentage score differences are percentage points.
4. Explain overall quality in plain language, then focus on important regressions and failures. Inspect actual vs expected answers, judge rationale, grounding, semantic similarity, and required action failures. A high average can hide a critical failure. A terse answer is not automatically worse, and semantic similarity is not proof of correctness.
5. Separate source gaps, incorrect test expectations, instruction problems, missing/failed tools, retrieval issues, and run infrastructure errors. Verify claims against sources and current configuration. Never invent retrieved evidence, latency, cost, or a causal explanation absent from the report.
6. Recommend the smallest appropriate fix. For instruction changes load instructions.md; for inaccurate cases load questions.md; for retrieval investigation use the response-quality skill. Review concrete changes before applying unless already explicitly authorized. After an authorized fix offer the same saved set as a controlled follow-up test and preserve the baseline.

Use `list_eval_runs` and `get_eval_run` for test runs and reports. The list contains only the most recent 25 runs; use a known run ID to read an older report. Completion of a run and completion of a remediation are separate outcomes.
